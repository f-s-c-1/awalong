# 房间系统设计

## 1. 房间生命周期

```
创建 → 等待加入(LOBBY) → 全员准备 → 游戏中(IN_GAME) → 结算 → 再来一局(回LOBBY) / 解散
                └── 房主解散 / 全员退出 / 空房 10 分钟 → 销毁
```

## 2. 创建房间流程

1. 用户点击「创建房间」→ 选择人数（5-10）与角色板子（默认推荐板子，可高级自定义）
2. 服务端生成 **6 位数字房间码**（全局唯一，Redis `SETNX`，有效期随房间生命周期）
3. 创建者自动入座 1 号位并成为房主
4. 返回房间码 + 分享卡片素材

房主权限：
- 修改人数/角色配置（仅 LOBBY 阶段）
- 踢人、转让房主、解散房间
- 全员准备后发起开局

## 3. 加入房间的三种方式

| 方式 | 实现 |
|---|---|
| 输入房间码 | 首页输入 6 位码 → REST 校验 → 进入房间页建立 WS |
| 分享链接 | 房间页「邀请好友」复制短链 `https://域名/r/xxxxxx`，微信内直接发送，点开直达房间 |
| 扫码/面对面 | 房间页前端生成二维码（内容为房间短链），同桌玩家扫码进入 |

加入校验顺序：房间存在 → 未开局（或该用户是掉线重连者）→ 未满员 → 分配最小空座位号。满员或已开局则以 **旁观者** 身份进入。

## 4. 座位与准备

- 座位固定 1~N 环形排列，决定队长轮转顺序
- LOBBY 阶段可点击空位换座
- 除房主外全员点击「准备」，房主的开局按钮才可用
- 人数不足配置人数时不可开局（房主可下调人数配置以适配当前人数）

## 5. 房间状态存储（Redis）

```
room:{code}          → Hash { ownerId, config, status, createdAt }
room:{code}:seats    → Hash { seat → { userId, nickname, avatar, ready, online, disconnectAt } }
room:{code}:watchers → Set  { userId }
user:room:{userId}   → String roomCode   # 反查，防多开、支持重连
```

- 用户同一时间只能在一个房间（`user:room` 反查，二次进房先退出旧房）
- 房间空置（无在线成员）10 分钟由定时任务回收

## 6. 异常场景

| 场景 | 处理 |
|---|---|
| 房主离开(LOBBY) | 房主自动转给座位号最小的在线玩家 |
| 房主离开(游戏中) | 房主标记保留，游戏不受影响 |
| 玩家 LOBBY 断线 | 保留座位 120s，超时释放座位 |
| 玩家游戏中断线 | 座位保留至局终，超时阶段按默认策略代操作 |
| 全员断线 | 游戏状态保留 10 分钟，供重连恢复 |
| 开局瞬间有人退出 | 开局操作加 Redis 分布式锁，先锁定成员快照再发牌 |

## 7. 反作弊约束

- 房间码不含语义，暴力枚举有频控（同 IP/用户每分钟 ≤10 次查询）
- 一个设备账号同房间只能占一个座位（uid 去重；无法完全阻止多设备多开，朋友局场景可接受）
- 旁观者收到的 `game.sync` 与普通玩家公开视角一致，无任何私密字段
