# 开发路线图与工程规划（H5 版）

## 1. 里程碑

### M0 — 基础设施（约 2-3 天）
- [ ] 域名备案确认、HTTPS 证书、云服务器
- [x] Docker Compose：nginx / server / livekit / redis / mysql（`deploy/`，未在真实服务器验证）
- [x] monorepo 初始化（web / server / shared）

### M1 — 可玩 MVP（约 3 周）
- [x] 服务端：Fastify 骨架、匿名账号 JWT、WS 网关、房间系统（创建/加入/座位/准备）——内存存储，Redis 待接
- [x] 游戏状态机：默认板子、完整流程（夜晚→组队→表决→任务→刺杀→结算），46 个单测含五人局端到端
- [x] 前端骨架：Vue3 + Pinia + 路由、WS/REST 服务层、封面/欢迎/加入/大厅/桌面/结算/规则七页与 SeatRing/QuestTrack/PhaseBar 组件（类型检查通过、可构建；视觉仅封面套完，其余页按画板精修中）
- [x] 桌面交互：夜晚发牌（翻牌 + 视野名单 + 确认，长按复看）、队长选人二次确认、表决牌与同步亮票、任务出票（正义方锁失败牌）与逐张揭晓、刺杀选人、轮流发言「说完了」、阶段横幅、战局记录抽屉、私人标记面板、再来一局回大厅（`game.reset`）
- [x] 沟通：文字快捷短语（chips 5 秒限频 + 头像气泡）
- [x] 发言秩序：默认轮流发言（可切自由）；发言期间服务端拒绝表决并只给当前发言者开麦，说完一圈恢复自由
- [x] 账号：用户档案与战绩以 JSON Lines 落盘（`DATA_DIR`），重启不丢 uid；首页可修改名号 / 退出登录
- [ ] 断线重连、超时代投、切后台状态拉齐
- 验收标准：5-10 人真机（微信内打开链接）完整跑通一局，无需口头解释规则

### M2 — 实时语音（约 1.5 周，无资质阻塞）

- [x] 降级：不支持 WebRTC / 服务端未配置 → 提示改用快捷短语；回前台恢复音频
- [ ] 真机联调：iOS 微信 / 安卓微信各一台跑通开麦、闭麦、刺杀私聊
- [ ] 轮流发言模式下非发言者音量压低（客户端 `RemoteAudioTrack.setVolume`）

## 2. 仓库结构（monorepo）

```
awalong/
├── docs/               # 设计文档（本目录）
├── web/                # Vue 3 + Vite 移动端 H5
│   ├── src/views/      # Home / Room / Game / Result / Rules
│   ├── src/components/ # SeatRing / RoleCard / VotePanel / QuestTrack / VoiceBar
│   ├── src/stores/     # Pinia
│   └── src/services/   # ws.ts / api.ts / voice.ts
├── server/             # Fastify + ws 服务端
│   ├── src/modules/    # auth / room / game / voice / gateway
│   └── test/           # 状态机单测(重点：规则判定全覆盖)
├── shared/             # 前后端共享协议类型(消息 type、枚举)
└── deploy/             # docker-compose.yml / nginx.conf / livekit.yaml
```

## 3. 质量要求

- 游戏状态机单元测试全覆盖：各人数配置的任务判定、5 次否决、第 4 轮双失败票、刺杀分支、超时代投
- 协议类型放 `shared/` 前后端共同引用，杜绝字段漂移
- 服务端所有阶段流转打审计日志（roomId + version + 事件），可回放
- 真机兼容清单：iOS 微信、安卓微信、iOS Safari、安卓 Chrome 各至少一台走通语音

## 4. 已确定决策

| 决策 | 结论 |
|---|---|
| 产品形态 | 移动端 H5（微信内链接传播），不做小程序 |
| 语音 | 自建 LiveKit，无平台资质门槛 |
| 账号 | 设备匿名账号 + 昵称头像，不接微信 OAuth |
| 封面视觉 | 圣剑徽章主方案已定稿（设计画布） |

3. 音效与角色插画素材来源（自绘 SVG / 购买素材包）
