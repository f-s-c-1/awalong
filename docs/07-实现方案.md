## 2. 服务端关键实现

### 2.1 游戏状态机：纯 reducer + 副作用分离

```ts
// server/src/modules/game/fsm.ts
type Effect =
  | { kind: 'broadcast'; msg: ServerMsg }             // 经视角过滤后发给全房间
  | { kind: 'secret'; seat: number; msg: ServerMsg }  // 定向发给某座位
  | { kind: 'timer'; ms: number }                     // 为当前阶段设定超时
  | { kind: 'voice'; policy: VoicePolicy }            // 语音权限变更
  | { kind: 'persist' };                              // 对局结束落库

export function reduce(state: GameState, action: Action): { state: GameState; effects: Effect[] }
```

- reducer 不做 I/O，所有随机数由调用方注入（`rng`），便于单元测试重放
- 每次 reduce 后 `version + 1`，写回 Redis（`SET game:{room}` JSON），并按 effects 执行副作用
- **超时计时器带版本号**：`setTimeout(() => dispatch({type:'TIMEOUT', version}), ms)`，reducer 里 `action.version !== state.version` 直接忽略，杜绝过期计时器触发
- **每房间串行**：`GameService` 内按 roomId 维护一个 Promise 队列（或 async-mutex），同一房间的 action 严格顺序执行，避免并发写 Redis 竞争

### 2.4 WebSocket 网关

- `@fastify/websocket`，连接 URL 携带 `?token=JWT`（浏览器 WS 无法自定义 header）
- 连接建立 → 校验 JWT → 查 `user:room:{uid}` → 在房间则加入连接表并补发 `room.sync` / `game.sync` / `game.secret`
- 心跳：服务端每 15s ping，两次无 pong 标记离线并广播 presence；座位保留逻辑走 Redis `disconnectAt`
- 入站消息用 zod 校验 schema，非法消息直接断开
- 每条出站消息带 `version`，客户端丢弃小于本地版本的消息

### 2.5 Redis 数据与并发

```
room:{code}            Hash    ownerId / settings / status
room:{code}:seats      Hash    seat -> {uid,nickname,avatar,ready,online,disconnectAt}
game:{code}            String  GameState JSON
game:{code}:log        List    审计日志（action + version + ts）
user:room:{uid}        String  反查
```

- 房间码：`randomInt(100000, 999999)` + `SETNX room:{code}`，冲突重试
- 开局：`SET room:{code}:starting NX EX 5` 作为锁，锁内快照座位再发牌

### 2.6 语音（LiveKit）

```ts
// POST /voice/token
const at = new AccessToken(apiKey, apiSecret, { identity: `seat-${seat}`, ttl: '2h' });
at.addGrant({ roomJoin: true, room: code, canPublish: true, canSubscribe: true });
```

- 阶段联动用 `RoomServiceClient`：
  - 全员静音：`mutePublishedTrack(room, identity, trackSid, true)` 逐人执行
  - 刺杀阶段：`updateParticipant(room, identity, undefined, { canPublish: false, canSubscribe: false })` 对正义方执行，邪恶方保持全权限——正义方此时既听不到也说不了，无需逐轨道控制订阅
  - 结算：恢复全员权限
- LiveKit 房间名 = 游戏房间码；对局结束调用 `deleteRoom`

### 2.7 落库

- 对局结束时 `persist` 效果把 `GameState.history` 写入 `matches / match_players / match_rounds`
- Redis 中的 game 键设 24h 过期，供"再来一局"与掉线复盘

## 3. 前端关键实现

### 3.1 基础设施
- 尺寸：`html { font-size: calc(100vw / 39) }`（1rem = 10px @390），容器 `max-width: 480px` 居中；安全区用 `env(safe-area-inset-*)`
- 设计令牌写成 CSS 变量（`--bg #141019` 等），不引 UI 库——所有组件按画板自绘
- 字体：**不要直连 Google Fonts**（国内不可达）。用 fontmin 把 Noto Serif SC 子集化到实际用到的字（标题、角色名、阶段名约 200 字，<100KB），Cinzel 只保留大写字母，自托管
- 路由：`/`、`/r/:code`、`/game`、`/result`、`/rules`；`/game` 与 `/result` 加守卫，无房间态则回首页

### 3.2 服务层
- `ws.ts`：指数退避重连（1s→2s→4s→上限 15s）、心跳、按 `version` 去重、`visibilitychange` 回前台主动发 `sync.request`
- `api.ts`：匿名注册（首次进入自动生成 uid，JWT 存 localStorage）、房间查询、语音 token
- `voice.ts`：封装 `livekit-client` 的 Room；仅在用户点击"开启麦克风"后 `connect`；远端音轨统一挂到一个 `<audio>` 池；`navigator.wakeLock` 防息屏
- 时间：`phase.change` 携带服务端时间戳，客户端计算 offset 后再倒计时，避免手机时钟偏差

### 3.3 状态与组件映射（与画板一一对应）

| 画板 | 组件 | 说明 |

| 阶段条 | `PhaseBar` | 文案 + 倒计时（最后 5 秒变红 + `navigator.vibrate`） |

### 3.4 动画时间线
- 表决亮票：收到 `team.reveal` 后所有座位卡牌同时翻开（`transition-delay: 0`），500ms 后阶段条更新结果
- 任务揭晓：收到 `quest.reveal` 后逐张 600ms 翻开，翻到 F 时全屏红光 100ms + 振动
- 阶段横幅：`phase.change` 触发 800ms 横幅，所有动画用 `prefers-reduced-motion` 降级

### 3.5 分享
- 房间链接 `https://域名/r/483920`，`navigator.clipboard`；二维码用 `qrcode` 包画到 canvas
- 战报长图：用 canvas 手绘（不用 html2canvas，微信内兼容性差），生成 `toDataURL` 后展示为 `<img>` 让用户长按保存

## 5. 部署（单机）

```yaml
# deploy/docker-compose.yml（要点）
services:
  nginx:    ports 80/443；静态 web；/api → server:3000；/ws 升级；/rtc → livekit:7880
  server:   env REDIS_URL / MYSQL_URL / LIVEKIT_KEY / JWT_SECRET
  livekit:  ports 7880, 7881, 50000-60000/udp；config: use_external_ip、turn(tls 5349 或复用 443)
  redis / mysql
```

- 证书：acme.sh 自动续签
- **TURN 必开**：公司 WiFi / 校园网常封 UDP，LiveKit 内置 TURN 走 TLS 443 兜底
- 云安全组放行 UDP 50000-60000

## 6. 实施顺序（M1 三周的竖切法）

1. **第 1 周**：`shared` 规则 + `server` reducer 及全部单测 → 房间模块 + WS 网关 → 一个纯文字的调试前端跑通完整一局（不做视觉）
2. **第 2 周**：按画板实现 SeatRing / QuestTrack / 各阶段操作区 / 身份牌 / 表决与揭晓动画；断线重连、计时器、切后台拉齐
3. **第 3 周**：战局记录、私人标记、结算页与战报图、分享链接与二维码；真机在微信内跑 5-10 人局，修兼容问题
4. **M2**：LiveKit 部署 + 语音接入 + 阶段闭麦
