# 线上语音对话方案

阿瓦隆的核心体验是"发言与辩论"，语音是刚需。小程序端实时语音有明确的平台门槛，方案按优先级给出三档。

## 1. 方案对比

| 方案 | 延迟 | 成本 | 门槛 | 结论 |
|---|---|---|---|---|
| A. 腾讯云 TRTC 小程序 SDK | <300ms | 按用量计费（有免费额度） | 需企业主体 + 开通 live-pusher/live-player 类目权限 | **首选** |
| B. 微信群语音（游戏外） | 低 | 0 | 无 | **MVP 兜底** |
| C. 录音消息(对讲机模式) | 秒级 | 低 | 无特殊类目 | 备选，体验降级 |

### 方案 A：TRTC 实时语音房（正式版目标）

**前提条件（硬门槛，立项前先确认）：**
1. 小程序主体必须是 **企业主体**（个人主体无法开通 live-pusher/live-player 组件权限）
2. 类目要求：需属于开放实时音视频能力的类目（如：社交-直播、游戏-XX 等，以微信官方最新类目表为准）
3. 开通腾讯云 TRTC 服务，获取 SDKAppID

**接入架构：**
```
小程序 <live-pusher>(推本地音频) + <live-player>(拉每个远端玩家音频)
   │ UserSig 由游戏服务端用 SDKSecretKey 签发（绝不下发密钥）
   ▼
TRTC 房间(roomId = 游戏房间码) ←→ 腾讯云音视频后台
```

- 进游戏房间即自动进 TRTC 同名房间，纯音频模式（不开视频，省流量）
- 组件层建议直接用腾讯官方封装 `trtc-wx` 小程序组件，避免手管 pusher/player 生命周期

**与游戏阶段联动的闭麦策略（服务端下发 voice 权限位）：**

| 游戏阶段 | 麦克风策略 |
|---|---|
| LOBBY / 组队讨论 / 投票前 | 全员自由发言 |
| 夜晚看牌 | 全员强制静音（防漏音）|
| 任务出票中 | 全员静音，防止逼票语音暗示（可配置开关） |
| 刺杀阶段 | 仅邪恶方成员可互相通话（TRTC 分子房间或按 userId 定向 mute 好人侧拉流），正义方听不到 |
| 结算 | 全员自由发言 |

刺杀阶段的"阵营私聊"实现：服务端向正义方客户端下发指令停止拉取邪恶方玩家的音频流即可（简单可靠），无需真正切换 TRTC 房间。

**计费预估**：纯音频约 7 元/千分钟级别（以腾讯云现价为准）。一局 30 分钟 × 8 人 = 240 分钟 ≈ 1.7 元/局，初期用免费额度覆盖。

### 方案 B：微信群语音兜底（MVP 阶段）

- 房间页提供「邀请进微信群」引导，玩家自建群后使用微信群通话
- 优点：零开发、零成本、无资质要求；缺点：无法做阶段性闭麦、体验割裂
- 适合第一版快速验证玩法，游戏内保留文字快捷短语（"我上""反对""1 号可疑"等一键发送）

### 方案 C：对讲机模式

- `wx.getRecorderManager` 录音 → 上传 COS → 房间内广播语音条自动播放
- 无实时性，只做没有 TRTC 资质时的过渡

## 2. 实施路线

1. **MVP**：方案 B + 游戏内文字快捷短语 + 表情
2. **V1.0**：企业主体认证 + 类目审核通过后接入 TRTC（方案 A），保留 B 作为降级
3. **降级链路**：TRTC 初始化失败 / 无权限 → 自动提示切换微信群语音

## 3. 语音相关服务端接口

```
POST /voice/usersig      # 校验用户在房间内后签发 UserSig（有效期2h）
WS   voice.policy        # 阶段切换时推送 { muteAll, allowSeats[], blockPullSeats[] }
```

## 4. 风险提示

- live-pusher/live-player 权限与类目政策随微信调整而变化，开发前以《小程序实时音视频权限申请》官方文档最新版为准
- 语音内容安全：TRTC 可开启腾讯云音频审核（涉政涉黄检测），上线前按平台要求评估是否必须接入
